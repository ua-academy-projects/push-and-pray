# Architecture decisions that prevent regressions

This is a short record of consequential mode-dependent or superseded choices, not a chronology. Historical decisions came from project context; the linked repository implementation is authoritative for what runs now. See [current architecture](architecture-current.md) and [mentor requirements](mentor-requirements.md).

| Decision | Consequence now |
| --- | --- |
| Redis-backed UI sessions were replaced for postgres_extensions. | This mode uses PostgreSQL session storage with hstore, pgcrypto, pg_cron, and sliding expiry. Redis remains valid in managed mode; do not reintroduce it globally or remove it globally. See [UI session selection](../services/ui/backend/src/ui_service/main.py) and [migration](../database/migrations/003_create_ui_sessions.sql). |
| RabbitMQ was not globally removed when PGMQ was added. | PGMQ is the postgres_extensions event path; RabbitMQ is the managed-mode path. Fetcher and History both branch on database_mode. See [database modes](database-modes.md), [Fetcher config](../services/fetcher/internal/config/config.go), and [History messaging](../services/history/src/history_service/messaging.py). |
| SSH and proxy settings were removed from group_vars. | The [inventory plugin](../infrastructure/ansible/oilscope/platform/plugins/inventory/oilscope.py) owns cloud discovery, bastion routing, and host-specific SSH arguments. Do not create a second group_vars source for the same connection topology. |
| A temporary Prometheus/Blackbox approach was superseded by native monitoring. | Current infrastructure uses AWS CloudWatch, GCP Cloud Monitoring, and Azure Monitor. Do not restore parallel Prometheus/Blackbox roles solely because older project history mentions them. See [monitoring map](architecture-current.md#public-https-and-monitoring). |
| Root locals and Cloudflare placement were deliberately simplified. | Root [locals.tf](../infrastructure/terraform/locals.tf) normalizes shared config and the default bastion; [cloudflare.tf](../infrastructure/terraform/cloudflare.tf) owns Cloudflare defaults and UI public-IP derivation. Keep new provider-specific resolution in provider modules unless a task requires a justified exception. |
| Compose is no longer the inspected aggregate deployment path. | The [deploy_workloads.yml](../infrastructure/ansible/oilscope/platform/playbooks/deploy_workloads.yml) imports database then K3s playbooks. Individual Compose playbooks remain as a legacy path; the aggregate path is K3s. No cloud rollout is proven by local syntax checks. |
| Multi-cloud Terraform support is not a cross-cloud Kubernetes guarantee. | K3s servers and agents join the selected primary server's private address, while the provider networks have no established cross-cloud peering. A mixed-cloud project config can be valid for infrastructure without being a working single K3s cluster. See [K3s role](../infrastructure/ansible/oilscope/platform/roles/k3s/tasks/main.yml) and [network map](architecture-current.md#network-ssh-and-secrets). |
